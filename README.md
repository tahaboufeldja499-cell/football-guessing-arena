# ساحة تخمين النجوم — Football Guessing Arena

لعبة تخمين لاعبي كرة القدم لشخصين من جهازين مختلفين: غرفة خاصة، بطاقة سرّية لكل لاعب، أسئلة حرّة أو سريعة، وخصمك هو من يجيب بنعم أو لا، ثم تخمين ونقاط وجولات. مبنيّة بـ Next.js 14 + TypeScript + Tailwind + Supabase (PostgreSQL + Realtime + Anonymous Auth + RLS).

> **حالة المشروع بصدق:** الكود مكتوب بالكامل، لكنه **لم يُشغَّل ولم يُختبر** بعد، لأن بيئة الكتابة بلا إنترنت (لا تثبيت حزم ولا اتصال بـ Supabase). نجح فحص صياغة كل ملفات TypeScript، لكن لم يُجرَ فحص أنواع كامل ولا تشغيل SQL. اتبع `TESTING.md` بعد الإعداد وأصلح ما يظهر.

## الإعداد

1. أنشئ مشروعًا على https://supabase.com
2. فعّل **Authentication ← Providers ← Allow anonymous sign-ins** (هوية الضيف).
3. افتح **SQL Editor** وشغّل بالترتيب: `supabase/schema.sql` ثم `supabase/seed.sql` ثم `supabase/002_legends.sql` (عمود الأساطير + أكثر من 100 أسطورة معتزلة، ويصلح أيضًا لمن شغّل schema.sql سابقًا).
4. انسخ `.env.example` إلى `.env.local` وضع القيمتين من **Project Settings ← API**:
   `NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_ANON_KEY` (المفتاح العام فقط، **لا تضع service_role أبدًا**).
5. `npm install` ثم `npm run dev` وافتح http://localhost:3000
6. للتجربة من هاتفين: انشر المشروع (Vercel: استورد المستودع وأضف نفس المتغيرين) أو افتح الخادم المحلي عبر عنوان شبكتك.

بدون الخطوة 4 تعرض الصفحة رسالة إعداد، ولا تدّعي أن الاتصال يعمل.

## كيف يعمل الأمان

- **لا كتابة مباشرة على الجداول:** RLS مفعّل على كل الجداول وبلا أي سياسة INSERT/UPDATE/DELETE. كل تغيير يمر عبر دوال `SECURITY DEFINER` (`create_room`, `join_room`, `pick_secret`, `ask_question`, `answer_question`, `make_guess`, ...) التي تتحقق من العضوية والدور والحالة داخل الخادم.
- **البطاقة السرّية** في جدول `secret_picks` لا يقرأ منه المستخدم إلا صفّه (`user_id = auth.uid()`)، والجدول **غير مضاف لـ Realtime**. لا تُكشف بطاقة الخصم إلا عبر جدول `rounds` بعد انتهاء الجولة.
- يُحسم التخمين الصحيح على الخادم؛ المتصفح لا يعرف بطاقة الخصم أصلًا.
- موانع: سؤال خارج الدور، سؤالان معًا، الإجابة عن سؤالك، تعديل الإجابة، تكرار نفس التخمين، انضمام لاعب ثالث، سؤالان خلال أقل من ثانية، نص فارغ أو أطول من 200 حرف.
- الهوية: جلسة ضيف مجهولة مرتبطة بالمتصفح (مسح بيانات المتصفح يفقدك الجلسة).

## قواعد اللعب المنفَّذة

- 3 جولات (قابل للتغيير في `rooms.total_rounds`)، نقطة لفائز كل جولة، ويبدأ اللاعب 1 الجولات الفردية والآخر الزوجية.
- **التناوب:** بعد أن يجيب الخصم، **ينتقل الدور إلى المجيب** (ليسأل أو يخمّن). اخترت هذا لأن صياغة المواصفات الحرفية (يبقى الدور مع السائل) تسمح للسائل بالسؤال بلا نهاية. لعكسه عدّل سطر `update public.rooms set pending_question = null, turn_uid = u` في `answer_question`.
- **التخمين الخاطئ** يُفقدك الدور فقط، ولا يُسمح بتكرار نفس اللاعب في الجولة.
- **الانسحاب/الانقطاع:** من يغادر أثناء المباراة يخسر. وإن غاب الخصم أكثر من 60 ثانية يظهر لك زر «أعلن فوزك».
- **إعادة المباراة** تصفّر النقاط وتبدأ جولات جديدة، وتحفظ نتيجة المباراة السابقة في `rooms.last_match`.

## ما ليس موجودًا بعد

- **لوحة إدارة داخل التطبيق:** لإضافة لاعبين استخدم Table Editor أو SQL في لوحة Supabase (وهي محمية بحسابك). مثال: `insert into footballers (name_ar,name_en,nationality,club,league,position) values (...)`.
- **صور اللاعبين:** `photo_url` فارغ عمدًا، وتظهر مكانه حروف ملوّنة. ضع صورًا مرخّصة بنفسك: `update footballers set photo_url='...' where name_en='...'`.
- **بيانات اللاعبين تجريبية** (51 لاعبًا) وأنديتها قابلة للتقادم، فراجعها قبل النشر.
- الإحصائيات في الصفحة الرئيسية غير معروضة لأنه لا توجد بيانات حقيقية لها بعد.
- لا حماية متقدمة من الإزعاج (rate limit على مستوى الشبكة)؛ الموجود حدّ سرعة للأسئلة وحدّ طول فقط.
- واجهة إنجليزية غير مفعّلة، لكن النصوص مجمّعة في المكوّنات لتسهيل نقلها لاحقًا.

## هيكل الملفات

```
supabase/schema.sql   الجداول + RLS + دوال الخادم + Realtime
supabase/seed.sql     لاعبون تجريبيون
src/lib/              عميل Supabase، hook المزامنة اللحظية، الأنواع، الأخطاء، الأصوات
src/components/       شاشات الصالة والاختيار والمباراة والتخمين والنهاية
src/app/              الصفحة الرئيسية وصفحة الغرفة /room/[code]
```

## صور اللاعبين والأعلام
- **الأعلام:** حزمة `flag-icons` (MIT) تُثبَّت مع `npm install` وتظهر في خانة العلم بالبطاقة الكاملة.
- **صور اللاعبين:** `CONTACT_EMAIL=بريدك@مثال.com npm run photos` يجلب لكل لاعب صورته من ويكيميديا كومنز ويقبل الرخص المفتوحة فقط (CC0 / CC BY / CC BY-SA / ملكية عامة)، ويحفظها في `public/players/` ويسجّل المصوّر والرخصة في `public/players/ATTRIBUTION.json` (تعرضها صفحة `/credits`)، ويولّد `supabase/003_photos.sql` تشغّله في SQL Editor. يكمل من حيث توقف، وما فشل يُطبع مع السبب (غالبًا تضيف اسم المقالة في `TITLE_OVERRIDES` داخل السكريبت).
- راجع الصور المنزّلة بعينك (بعضها قد يكون صورة جماعية أو بعيدة)، واحذف الملف وشغّل السكريبت ثانية لتغيير صورة. استعمال صور أشخاص في مشروع **تجاري** يحتاج مراجعة قانونية لحقوق الشخصية حتى لو كانت الرخصة مفتوحة.

## اللعب المحلي ومعرض اللاعبين (بدون Supabase)
- **/local** مباراة على جهاز واحد: إدخال الأسماء، اختيار الحزم (النجوم / الأساطير / الجزائريون / العرب) وعدد الجولات (1 أو 3 أو 5)، ثم تمرير الجهاز. قبل كل تمرير تظهر **شاشة تغطية** تستبدل الصفحة كلها (لا طبقة شفافة)، ولا يُعرض لاعبك السري إلا لك. الإجابات: نعم / لا / غير متأكد. القواعد نفس الأونلاين: تناوب صارم، والتخمين الخاطئ يُفقدك الدور ولا يتكرر.
- **/gallery** يعرض كل البطاقات بفلاتر الحزم والبحث، ويكبّر أي بطاقة بإطارها (عادي/أساطير) وعلمها.
- البيانات من `src/data/footballers.ts` (مولَّد من ملفات SQL). بعد أي تعديل على `seed.sql` أو `002_legends.sql` شغّل `npm run gen:data`. وإن وُجد `public/players/ATTRIBUTION.json` (من `npm run photos`) تظهر الصور تلقائيًا.
- التخمين في المحلي باختيار البطاقة (مثل الأونلاين الحالي). التخمين بكتابة الاسم غير مبني بعد.

## الصوت
- موسيقى (قائمة / مباراة / فوز) ومقدمة دخول ومؤثرات (نقر، اختيار، سؤال، سؤال وارد، نعم، لا، غير متأكد، تخمين خاطئ، كشف البطاقة، تغيّر الدور، نهاية الجولة، فوز، تغطية) كلها **مولَّدة بالكود** (WebAudio). لا يبدأ أي صوت قبل أول ضغطة (سياسة المتصفح)، ولذلك تبدأ المقدمة بزر «اضغط للبدء».
- الإعدادات (من القائمة الرئيسية ← الإعدادات): تشغيل/كتم ومستوى مستقل لكل من الموسيقى والمؤثرات، وإيقاف المقدمة. زر الصوت داخل الغرفة يكتم الكل.
- لموسيقى حقيقية مرخّصة: ملفات mp3 في `public/audio` (انظر `public/audio/README.md`).

## المراكز التفصيلية (CF, SS, RWF, LWF ...)
- لكل لاعب مركز بأسلوب eFootball: GK حارس • CB قلب دفاع • LB/RB ظهير • DMF وسط مدافع • CMF وسط • LMF/RMF وسط جناح • AMF وسط مهاجم • LWF/RWF جناح • SS مهاجم ثانٍ • CF رأس حربة.
- تظهر على البطاقة (اللوحة الصغيرة)، وتحت اسم اللاعب في الشبكات، وفي نافذة المعرض.
- المراكز في `scripts/positions.mjs` (اجتهاد مني، عدّل ما لا يعجبك) ثم `npm run gen:data` فيُحدَّث `src/data/footballers.ts` ويُولَّد `supabase/004_positions.sql`. للأونلاين شغّل `004_positions.sql` في SQL Editor (آمن عند التكرار).

## تطبيق أندرويد (APK) — Capacitor
الفكرة: نفس الموقع يُبنى كملفات ثابتة (`BUILD_TARGET=app` ← مجلد `out`) ويُلفّ داخل تطبيق أندرويد. التطبيق يعمل **بدون إنترنت** في اللعب المحلي والمعرض، ويحتاج إنترنت للأونلاين (Supabase). نفس التصميم، مع: شاشة عمودية، مناطق آمنة، أهداف لمس أكبر، شريط حالة داكن، وزر الرجوع (يخرج من الرئيسية).

**المتطلبات على جهازك (مرة واحدة):** Node 18+ • Android Studio (يثبّت Android SDK وJDK) • فعّل المتغيرات في `.env.local` (نفس الموقع).

```
npm install
npm run app:init     # أول مرة: بناء + إنشاء مشروع android + أيقونة وشاشة إقلاع + مزامنة
npm run app:apk      # يبني الملف: football-arena.apk في مجلد المشروع
```
بعد أي تعديل في الكود أعد `npm run app:apk` فقط. السكريبت يكتب `android/local.properties` تلقائيًا إن وجد الـ SDK في مكانه المعتاد، ويستعمل JDK الخاص بـ Android Studio.

- **بدون Android Studio:** ارفع المشروع إلى GitHub، وأضف Secrets (`NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_ANON_KEY`)، ثم Actions ← Build Android APK ← Run workflow، ونزّل الملف من Artifacts.
- **روابط الدعوة داخل التطبيق:** عنوان التطبيق الداخلي localhost، فضع في `.env.local` القيمة `NEXT_PUBLIC_SITE_URL=https://موقعك.vercel.app` لتصير الروابط صالحة. (الانضمام بالرمز يعمل دائمًا.)
- **رقم الحزمة والاسم:** في `capacitor.config.json` (`appId`: `com.footballarena.app`). غيّره قبل `app:init` إن أردت.
- هذا APK تجريبي (debug) للتثبيت المباشر. النشر على Google Play يحتاج حزمة AAB موقّعة (خطوة لاحقة).
- صور اللاعبين التي تنزّلها في `public/players` تدخل داخل التطبيق (تزيد حجمه).
- غُيّرت صفحة الغرفة من `/room/ABC123` إلى `/room?code=ABC123` (يلزمها التصدير الثابت).

### مشكلة: التطبيق يقول «المشروع يحتاج إعداد Supabase»
معناه أن التطبيق بُني **بدون مفاتيح** (والمفاتيح تُدمج وقت البناء، فلا تفيد إضافتها بعد التثبيت). على GitHub: Settings ← Secrets and variables ← Actions ← تبويب **Secrets** ← أضف `NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_ANON_KEY` بنفس قيم `.env.local`، ثم أعد تشغيل Build Android APK، وحذف التطبيق القديم من الهاتف قبل تثبيت الجديد. البناء الآن يفشل برسالة واضحة إن غابت المفاتيح، ويتأكد أنها دُمجت. اللعب المحلي والمعرض يعملان حتى بدون مفاتيح.
